# Opexa – going live

Three pieces run in production:

| Piece | Where | Repo |
|---|---|---|
| Database | MongoDB Atlas (Mumbai region) | – |
| API (`opexa-backend`) | Render web service `opexa-api` (or any Docker host) | 11nov26-opexa-back |
| Web app (`opexa-app`) | Vercel | 11nov26-opexa-front |
| Phone apps (`opexa-app`) | Expo EAS builds → APK / Play Store / App Store | 11nov26-opexa-front |

Secrets are typed into the hosting dashboards. They are never committed (`.env` stays in `.gitignore`).

---

## 1. Database – MongoDB Atlas

1. Use the existing cluster (the one in `MONGODB_URI`). For production, pick at least an **M10** tier. That tier gives you daily backups and point-in-time restore. The free M0 tier has no backups.
2. **Database Access**: create a user `opexa-api` with *Read and write to any database*. Use a long random password.
3. **Network Access**: add `0.0.0.0/0`. Render has no fixed IP on the starter plan, so access is protected by the user's password instead. If you move to a host with a fixed outbound IP, allow only that IP.
4. Copy the connection string and set the database name to `opexa`:
   `mongodb+srv://opexa-api:<password>@<cluster>/opexa?retryWrites=true&w=majority`

## 2. API – Render

1. On Render, go to **New → Blueprint** and pick the `11nov26-opexa-back` repo. Render reads `render.yaml` and creates the `opexa-api` service in the Singapore region, with a health check on `/api/v1/health`.
2. Fill in the secret values it asks for:
   - `MONGODB_URI`: the string from step 1.
   - `EXPO_ACCESS_TOKEN`: the Expo robot token. It is the same value as `Expo_URL` in your local `.env`.
   - `CORS_ORIGIN`: the web app address(es), comma separated, e.g. `https://opexa.globalairtech.in,https://opexa-app.vercel.app`.
   - `JWT_ACCESS_SECRET` is generated by Render automatically. If you change it, everyone has to sign in again and old print/photo links stop working.
3. Use the **Starter** plan (or higher), not Free. On the Free plan the server sleeps when idle. While it sleeps, the 15-minute reminder job, attendance auto-close and service/PM jobs don't run, and the first request takes about 50 seconds.
4. (Optional) **Custom domain**: add `api.globalairtech.in` in Render, then create the CNAME record it shows at your domain registrar.
5. Check the deploy:
   ```
   npm run smoke -- https://opexa-api.onrender.com
   ```
   All four lines should say PASS: database connected, wrong password refused, data needs a login, security headers present.

**Other hosts:** the repo also has a `Dockerfile`. It runs as a non-root user, has a built-in health check and listens on port 5000. It works on Railway, Fly.io, AWS App Runner, or a VPS with `docker run -p 5000:5000 --env-file .env opexa-api`.

The API refuses to start in production without `JWT_ACCESS_SECRET` and `MONGODB_URI`. On deploys it shuts down cleanly when the host sends SIGTERM, finishing any open requests first.

## 3. Web app – Vercel

1. On Vercel, go to **Add New → Project** and import `11nov26-opexa-front`. Vercel reads the build settings from `vercel.json`, so nothing needs changing.
2. Under **Environment Variables**, set `EXPO_PUBLIC_API_URL` = `https://opexa-api.onrender.com/api/v1` (or your custom API domain + `/api/v1`).
3. Deploy. To use your own address, add a domain such as `opexa.globalairtech.in` and create the DNS record Vercel shows.
4. Put the final web address into the API's `CORS_ORIGIN` (step 2.2). Without it the browser blocks the API calls.

Every push to `main` redeploys the web app.

## 4. Phone apps – Expo EAS

One-time setup, run in `opexa-app` on your computer:
```
npx eas login
npx eas init          # links the app to Expo; writes the projectId used for push alerts
```
Commit the `app.json` change that `eas init` makes.

**Android push alerts** need Firebase:
1. Create a Firebase project and add an Android app with package `com.globalairtech.opexa`.
2. Download the **service account key** (Project settings → Service accounts → Generate new private key).
3. Run `npx eas credentials`, choose Android → production → Google Service Account → *Push Notifications (FCM V1)*, and upload the key.

**Building** happens from GitHub. The `EXPO_TOKEN` secret is already added to the repo:
- Go to **Actions → Build Android app → Run workflow**.
  - `preview` gives an **APK** you can send to site staff to install directly.
  - `production` gives the **Play Store bundle**. Upload it in Play Console. The listing text goes in `docs/playstore-listing.md`.
- **Build iPhone app** needs an Apple Developer account ($99/yr). Run `npx eas credentials` once to link it.
- Before building, check that the API URL in `eas.json` (`preview` and `production` → `env.EXPO_PUBLIC_API_URL`) matches your real API address. It is set to `https://opexa-api.onrender.com/api/v1`.

**Quick fixes without a new store release** (optional): run `npx expo install expo-updates && npx eas update:configure` once and commit the result. After that, **Actions → Push app update** sends JavaScript-only changes straight to installed phones.

## 5. After going live

- **First login:** sign up once on the web app with the Global Airtech owner account. That account is the MD/owner and can add the team from there.
- **Office location:** set it in attendance settings. Each project's site location is set on the project.
- **Monitoring:** turn on Render notifications for failed deploys and health checks. In Atlas, set alerts for disk usage and connection count.
- **Rolling back:**
  - API: on Render, go to Events → pick the previous deploy → *Rollback*.
  - Web: on Vercel, go to Deployments → previous one → *Promote to Production*.
  - Phones: build again from the previous commit, or publish an earlier update.
- **Restoring the database:** in Atlas, go to Backup → Restore, to a new cluster first, then switch `MONGODB_URI`.
- **Running more than one API instance:** this is safe. The background jobs only send each reminder once and only create each preventive-maintenance job once, even if two instances run them at the same time.
